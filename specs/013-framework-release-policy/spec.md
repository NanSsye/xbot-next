# Xbot 框架发布规范

状态：已确认，作为后续框架版本的发布与验收依据；不代表现有更新器已经实现。插件和技能不在本规范范围内。

**管理后台只上传一次完整的 Xbot 程序包，发布一个目标版本；用户端按需下载差异文件。**

| 环节 | 必须满足的要求 |
| --- | --- |
| 后台发布 | 管理员不选择来源版本。后台验证完整包，为目标版本提供含官方路径、大小和内容哈希的签名清单，以及可独立获取和校验的文件内容。同一目标版本只出现一条发布记录，不按旧版本建多条记录，也不允许用新内容覆盖已发布版本。 |
| 客户端下载 | 先验签目标清单，再比较本机文件。只获取新增、缺失或内容不同的目标文件；相同文件不传输，删除项不下载。不得先下载完整包再在本地筛选。兼容的旧版直接升级到目标版，无须安装中间版本。 |
| 本地修改 | 对比上次安装的可信官方清单、本机实际文件和目标清单。只删除上次受官方管理且目标已移除的文件。若更新将覆盖用户修改或新文件与本地文件同名，先列出冲突；取消则不改任何运行文件，同意才应用整次更新。 |
| 数据保护 | 完整包指官方程序和随版资源，不是部署目录的备份。数据库、媒体、密钥、实例配置和用户自装扩展不得作为更新目标。缺少可信基线时，不猜测文件归属、不静默删除或覆盖。 |
| 安装与恢复 | 先检查运行环境和迁移兼容性；不支持直升时说明原因并停止。文件全部校验通过后才应用，重启并检查实际服务及目标版本；失败则恢复并复验旧版。 |

**发布验收示例：** 后台只上传一次 `0.1.3`。分别从兼容的 `0.1.0` 和 `0.1.2` 检查更新，两端看到同一条 `0.1.3`，各自只请求需要的文件，均不请求中间版本。另测取消冲突、用户数据保留和健康检查失败回滚。历史 `0.1.3` Web 多包测试不能代替这项验收。
