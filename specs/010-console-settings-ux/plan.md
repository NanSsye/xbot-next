# 实施顺序与交付边界

1. 盘点字段：逐项记录现名、用户任务、默认可见性、权限、生效方式和现有入口。给无说明的字段写用途。交付新旧位置对照表，无字段失踪才进入下一步。
2. 先做首次配置与日常换模型的本地交互样稿。用未配置、已填写但停用、已配置待试聊三套虚构数据审阅，先定文案和操作顺序。
3. 接入模型设置：复用 ConfigCenter 的快照、敏感字段、差异提交、冲突和确认处理；将获取模型串联在确认保存成功之后。核对手动模型 ID 的服务端约束和启停语义；不凭前端推测连接状态。
4. 整理偏好与高级设置：保留已有字段、权限和配置键，搜索保留英文别名。复用通道页抽屉交互及现有对话页，不新建第二个配置服务或聊天窗口。
5. 本地验收：空配置走到试聊、已有配置只换模型、无列表服务、保存失败、发现失败后重试、关闭时保护草稿、键盘焦点、桌面及窄屏。核对写入差异不涉及其他设置。模拟流程通过不等于真实调用成功；真实服务验证须另获环境授权。

本次仅交付方案；实现后才更新运行页面节点。不计划改数据库或配置协议。若能力核对发现需要后端变更，先说明缺口与兼容策略再实施。分阶段提交；布局问题可回退对应前端变更，不清空用户配置、不覆盖密钥。生产发布单独确认。

实施已获确认，本次在本地一次完成。用单个快照驱动设置首页，复用现有 ConfigCenter 做按路径隔离的抽屉编辑器。新模型 ID 随默认模型一并追加到允许列表（保留其他模型），保存前展示变更。网页不自行发起付费试聊。
